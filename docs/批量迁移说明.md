# 自定义任务批量迁移

更新日期：2026-11-25（规范基线 2026-10-15）。适用于“冒险大转盘”的版本 1 JSON / TXT 自定义任务备份，不适用于内置教学数据。

元服务可以导出全部自定义任务，但每次导入最多 1000 条、文件不超过 1 MiB（1,048,576 字节）。超过限制时，不必删掉任务：在电脑上用工程附带的工具拆分，再逐份导入。

## 让 AI 帮你拆分

先在元服务“任务库 → 我添加的 → 导出任务”保存完整备份，复制到电脑。

> [!WARNING]
> 保留原设备和完整备份，切勿在公开对话或提示词中直接粘贴私人任务正文。

在已获取本案例的本地**码道 IDE**工作区（Windows 工程路径**必须**为纯英文、无空格）或云端工作区输入：

```text
我需要把冒险大转盘的自定义任务迁移到另一台设备。
请先让我提供本机备份文件的位置，不要让我把任务正文贴到公开对话。
使用当前工程的 tools/split-task-backup.mjs，调用已有 Node.js，
把文件拆到一个新的独立输出目录；不得改写、覆盖或删除原备份和已有文件。
每份必须同时满足最多 1000 条、最多 1 MiB（1,048,576 字节），
保留原任务顺序及字段内容。
生成后把各份 tasks 按顺序拼回核对与原任务完全一致，
告诉我条数和文件位置。
只报告统计，不输出私人任务正文；遇到无效记录先说明问题，不擅自删改。
```

> [!TIP]
> 拆分脚本由 AI 在工作区调用执行即可，不要求手写命令行；如需自行检查调用命令，参数形式为 `node tools/split-task-backup.mjs "<原备份文件.json>" "<新的输出目录>"`。

输入也可以是包含 JSON 的 TXT。输出目录的父目录须已存在，输出目录必须是新的；若目录已存在，工具直接停止，不覆盖文件。原备份超过 50 MiB 时，工具也会停止并要求另行评估。

> ✅ **完成标志**：各份拆分文件均不超过 1000 条且不超过 1 MiB，拼回后的任务序列与原备份完全一致，原备份未被修改。

## 在新设备恢复

1. 把输出的 `adventure-wheel-tasks-001.json`、`002.json` 等全部传到目标设备。
2. 打开“任务库 → 我添加的 → 导入任务”，按编号逐份选择，查看新增、重复与无效统计后确认。
3. 在原本为空的任务库中，新增总数应等于备份中按“类型 ＋ 正文”规则去重后的有效任务数；已有任务库合并时应扣除本地重复项。
4. 抽查任务正文、类型、程度和启用状态，包括停用项。确认全部恢复成功后，再自行决定是否清理原设备或备份。

> ✅ **恢复标志**：目标设备已完成全部拆分文件导入，抽查正文、类型、程度与启用状态无误。

> [!NOTE]
> 拆分不删重、不清洗文字，也不修改记录的字段；正常导入仍会去掉正文首尾空白，并按元服务规则处理重复项。拆分核对通过不代表另一台设备已导入成功，最终以目标设备的实际结果为准。

字段及去重规则见[任务文件格式](./任务文件格式.md)。备份是明文，请核对接收对象与文件保存位置。
