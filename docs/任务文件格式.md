# 冒险大转盘任务文件格式

核对日期：2026-10-01。依据当前 `TaskTransferPackageBuilder`、`TaskTransferValidator` 和 `TaskTransferService` 实现。

## 文件用途

- “导出任务”保存 `adventure-wheel-tasks-时间戳.json`。
- “分享我的任务”生成 `adventure-wheel-my-tasks.txt`，通过 `text/plain` 文件路由打开可接收应用。
- 两种扩展名的正文都采用 UTF-8 JSON；导入使用同一套校验。TXT 不支持一行一条任务的普通文本格式。
- 文件包含全部自定义任务，包括停用项；不包含内置任务、本地 ID、创建时间和更新时间。

## 可导入示例

将以下内容保存为 UTF-8 的 `.json` 或 `.txt` 文件，在“任务库 → 我添加的 → 导入任务”选择文件：

```json
{
  "format": "adventure-wheel-tasks",
  "version": 1,
  "tasks": [
    {
      "type": "dare",
      "level": "light",
      "text": "在十秒内说出三种水果",
      "enabled": true
    },
    {
      "type": "truth",
      "level": "medium",
      "text": "最近最开心的一件事是什么？",
      "enabled": false
    }
  ]
}
```

完成标志：确认框显示可导入条数；确认后两条任务进入“我添加的”，第二条保持停用。如果本地已经有相同任务，会计入重复条数。

## 字段与上限

| 字段 | 允许值 |
| --- | --- |
| `format` | 固定为 `adventure-wheel-tasks` |
| `version` | 当前只接受整数 `1` |
| `tasks` | 数组，单次最多 1000 条；文件最大 1 MB |
| `type` | `truth`（真心话）或 `dare`（大冒险） |
| `level` | `light`（轻松）、`medium`（适中）、`deep`（深入） |
| `text` | 字符串，去除首尾空白后非空，最多 30 个 Unicode 码点；普通中文字符和标点均计数 |
| `enabled` | 布尔值 `true` 或 `false` |

这不是 JSON Schema 验证器。当前实现校验以上必要字段，不主动拒绝额外字段，但额外字段不会保存或再次导出。正文长度使用 `Array.from(text).length`，某些组合 Emoji 可能计为多个字符。

## 合并规则

先统计有效、重复和无效任务，经用户确认后才写入本地。重复键由“任务类型 + 正文”形成，正文会忽略空白和英文大小写；挑战程度或启用状态不同不会把同一类型、同一正文变成新任务。

相同类型的重复内容不会覆盖已有记录；不同类型可以使用相同正文。有效的新任务重新生成本地 ID 和时间。损坏 JSON、未知格式、未知版本和超过文件或条数上限会拒绝整份文件；混合数组中的无效条目会跳过并计数。

## 传递与备份

已知数量边界：当前添加任务、合并多次导入和导出没有统一的任务总量上限，但单份导入文件最多接受 1000 条。2026-10-01 使用实际序列化及校验代码复测：1000 条可往返，1001 条导出后被整体拒绝导入。此问题尚未修复；超过 1000 条的用户不要仅依赖一个完整导出文件作为可直接恢复的备份，迁移前先保留原设备数据并验证目标设备导入结果。

分享成功启动只说明系统找到了接收入口。请在目标应用确认文件已收到，并在另一台设备完成导入，才算迁移成功。没有接收应用时可先使用“导出任务”保存 JSON，再自行传递。

文件内容为明文，发出前检查任务是否含私人信息。迁移完成之前保留原设备数据和备份。
