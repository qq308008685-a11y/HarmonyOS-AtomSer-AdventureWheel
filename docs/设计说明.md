# 冒险大转盘设计说明

核对日期：2026-11-25（源码架构核对）。本文以当前源码和 `build-profile.json5` 为依据，介绍可复用的实现思路。

## 页面与流程

- `EntryAbility` 加载 `SetupPage`。首页恢复上次玩法、数量和挑战程度，读取本地任务库。
- `SetupPage` 调用 `TaskEngine.pickForWheel()` 生成实际任务清单。用户可以重新生成，点击“确认开局”后才传给 `WheelPage`。
- `WheelPage` 管理轮次、结果卡片和已处理任务 ID，`WheelCanvas` 绘制转盘并处理旋转。
- `TaskLibraryPage` 提供内置内容浏览、自定义任务维护和文件迁移入口。

## 两层随机规则

开局抽样按玩法和最高挑战程度筛选。只有启用的本地任务参与，最多占 `floor(本局任务数 × 0.5)`，其余由内置任务补足。数组使用 Fisher–Yates 洗牌。

转盘命中使用 `WheelRoundState` 筛出本局未处理的任务，再从这些索引随机选择目标。用户交给下一位后，当前 ID 加入完成集合，扇区保留位置、变灰并显示“完成”。跳过后交接也会退出本局候选。

> [!NOTE]
> 完成集合不写入持久化存储。新开一局可能再次抽到之前玩过的任务。当前随机逻辑用于聚会娱乐，不适用于博彩或需要审计的抽签。

## 视觉与动画

转盘采用 ArkUI Canvas 绘制扇区、侧壁和文字，并用透视旋转呈现 2.5D 效果。先决定目标索引，再计算停止角度，使结果与指针对应。

旋转中禁用中心按钮，停止后依次展示扇区强调、命中圆环和居中卡片。结果卡片使用缩放、位移和透明度过渡，任务正文独立展示，避免把长文字塞进小扇区。

## 本地数据

`LocalTaskStore` 用 Preferences 保存 JSON，包含任务 ID、正文、类型、挑战程度、启用状态及时间。写入后调用 `flush()`。`PreferenceStore` 独立保存游戏设置。

`TaskTextRules` 将最多 30 个 Unicode 码点的规则用于输入、保存和导入；自定义任务同类型同正文去重时忽略空白和英文大小写。

文件迁移只保留可携带的任务字段，不携带本地 ID 和时间戳。导入先展示统计，再合并有效的新任务，不覆盖本地记录，详见[任务文件格式](./任务文件格式.md)。

## 文件能力与分享

导入导出使用系统文档选择器和用户选择的 URI，无需服务器或宽泛存储权限。导入先打开 URI 得到文件描述符，再检查大小和读取，文件句柄在 `finally` 中关闭。

分享把 JSON 正文写入 TXT，通过文件 URI、只读授权及 `ohos.want.action.sendData` 交给系统。当前实现没有使用 `ShareController`；目标应用的选择和接收行为由系统及接收方决定。启动接收入口不等于文件已送达。

## 兼容与验证

> [!IMPORTANT]
> 当前 `build-profile.json5` 配置为 `compileSdkVersion: "26.0.0"`、`targetSdkVersion: "26.0.0"`（API 26）、`compatibleSdkVersion: "6.0.0(20)"`（最低兼容 API 20），编译 SDK 使用配套工具链。编译版本不代表最低可安装版本，是否能在 API 20 正确运行仍需最低版本设备实测。

工程只声明手机（`entry/src/main/module.json5` 中 `deviceTypes: ["phone"]`）。已有 API 24 手机模拟器运行记录来自 2026-08-26 及 2026-10-02；历史规则测试与无签名构建结果见[发布前核对](./发布前核对.md)。扩展设备类型、大字体或多窗口体验时，应补充专项验证。
