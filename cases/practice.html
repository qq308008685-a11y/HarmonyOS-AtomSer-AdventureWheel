1. 案例概览

朋友聚会时，把手机放在大家面前，选好玩法与挑战程度，生成一张大转盘。每人点击一次，按结果完成任务，再交给下一位。这个案例帮助你把随机规则、交互动画和本地数据分开管理，也能迁移到活动抽签、学习练习等场景。

核心功能与体验

  1. 选择“真心话 / 大冒险 / 混合局”，设置 2–20 个任务和最高挑战程度。
  2. 点击“立即开始”，先看本局清单；不满意可“重新生成”，确认后才开局。
  3. 点击中心“开始”，转盘减速停下，突出命中扇区，以动画显示居中的完整任务卡片。
  4. 点击“交给下一位”，当前任务变灰并标记“完成”，本局不会再抽到；最后一项显示“完成本局”。不想做也可以交接跳过。
  5. 在“任务库”查看 190 条内置任务，或添加、编辑、启停、删除自己的任务；自定义正文最多 30 个字。
  6. 导出自定义任务为 JSON，或通过“分享我的任务”生成 TXT 交给接收应用；TXT 正文仍是 JSON，新设备可导入恢复。
开局前确认 转盘与完成标记 抽取结果

首页、任务库及完整原图见截图与教学素材索引。

技术方案一览

内置任务随工程打包，自定义任务与设置保存在本机。开局先筛选再随机组成清单，自定义任务最多占本局数量的一半。每次转动只从尚未处理的任务中选取，动画把指针停到对应扇区。

层级 技术/产品 兼容要求 作用
端侧 ArkTS / ArkUI，Stage 模型 手机元服务；目标 API 23，最低兼容 API 20 设置、任务库、转盘和结果交接
视觉 Canvas、透视变换与属性动画 当前 SDK 支持的原生能力 2.5D 转盘、减速、命中反馈和结果入场
数据 内置任务、Preferences、JSON UTF-8；自定义文件版本 1 本地持久化与文件迁移
文件 DocumentViewPicker、文件 URI、隐式 Want 选择器和接收应用须可用 用户选取文件或保存位置，分享 TXT
工具 码道 IDE、HarmonyOS Command Line Tools；DevEco Studio 可辅助准备模拟器和签名 SDK、Java、Node 与构建工具应匹配 AI 开发、打包、安装与运行

边界说明

  • 无服务器、无需游戏账号，不自动云同步。云端开发环境是开发入口，不是应用后端。
  • 完成状态只属于当前一局；重新开局可以遇到之前玩过的任务。转盘不用于博彩或需审计的抽签。
  • 分享的接收应用与后续动作由系统及接收方决定；对方实际取得文件才算传递成功。
  • 单份自定义文件最多导入 1000 条、大小不超过 1 MiB。当前添加和导出没有总量上限；备份超限时，使用工程附带的安全拆分工具，再逐份导入。步骤见批量任务迁移，恢复核对前保留原设备和完整备份。

超限备份的安全恢复

更新日期：2026-10-15。适用于“冒险大转盘”的版本 1 JSON/TXT 自定义任务备份，不适用于内置教学数据。

元服务可以导出全部自定义任务，但每次导入最多 1000 条、文件不超过 1 MiB。超过限制时，不必删掉任务：在电脑上用工程附带的工具拆分，再逐份导入。

让 AI 帮你拆分

先在元服务“任务库 → 我添加的 → 导出任务”保存完整备份，复制到电脑。保留原设备和备份，不在公开对话中粘贴私人任务正文。在已获取本案例的本地工作区输入：

我需要把冒险大转盘的自定义任务迁移到另一台设备。
请先让我提供本机备份文件的位置，不要让我把任务正文贴到公开对话。
使用当前工程的 tools/split-task-backup.mjs，使用已有 Node.js，
把文件拆到一个新的独立输出目录；不得改写、覆盖或删除原备份和已有文件。
每份必须同时满足最多 1000 条、最多 1 MiB，保留原任务顺序及字段内容。
生成后把各份 tasks 按顺序拼回核对与原任务完全一致，告诉我条数和文件位置。
只报告统计，不输出私人任务正文；遇到无效记录先说明问题，不擅自删改。

工具由 AI 调用即可，不要求你手写代码。熟悉命令行时也可在工程根目录运行：

node tools/split-task-backup.mjs "原备份文件.json" "新的输出目录"

输入也可以是包含 JSON 的 TXT。输出目录的父目录须已存在，输出目录必须是新的；若目录已存在，工具直接停止，不覆盖文件。原备份超过 50 MiB 时，工具也会停止并要求另行评估。

在新设备恢复

  1. 把输出的 adventure-wheel-tasks-001.json、002.json 等全部传到目标设备。
  2. 打开“任务库 → 我添加的 → 导入任务”，按编号逐份选择，查看新增、重复与无效统计后确认。
  3. 在原本为空的任务库中，新增总数应等于备份中按“类型＋正文”规则去重后的有效任务数；已有任务库合并时应扣除本地重复项。
  4. 抽查任务正文、类型、程度和启用状态，包括停用项。确认全部恢复成功后，再自行决定是否清理原设备或备份。
