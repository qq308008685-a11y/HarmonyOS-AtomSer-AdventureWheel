冒险大转盘实践操作

用现有工程完成“选玩法 → 确认任务 → 轮流转盘 → 管理本地任务 → 文件迁移”的闭环。建议先运行，再沿数据流阅读代码，最后独立验收。环境就绪后预计约 120 分钟，不含工具下载与签名准备。

验证边界：2026-09-30 已有 17 项纯逻辑测试通过及无签名 Release 构建成功记录；效果截图来自 2026-08-26 API 24 手机模拟器。本次新包设备运行、最低 API 20、真机表现，以及 TXT 实际接收与再次导入仍待补齐。

实践步骤

  1. 检查环境并打开工程

    目标：确认工具可用，避免把环境缺失误当作代码问题。

    操作：在 DevEco Studio 打开包含 AppScope/、entry/、build-profile.json5 的工程根目录，等待同步。核对配套 SDK、Node.js、Java 和 Hvigor；根构建配置的目标版本为 6.1.0(23)，最低兼容版本为 6.0.0(20)，编译 SDK 随 IDE。当前已有构建使用配套 API 26 SDK，这不代表最低设备版本变成 API 26。

    如使用 AI 辅助，可输入：

    我准备开发一个鸿蒙元服务。请先检查当前环境是否具备必要的开发工具，如果有缺失，先告诉我应该怎么处理，由我来决定。

    完成标志：IDE 识别 entry 模块，能打开 SetupPage.ets，同步没有阻断错误。不擅自安装或切换工具、不要求上传签名私钥。

  2. 构建并完成最短体验

    目标：先确认工程能构建，再检查基本交互。

    操作：通过 IDE 构建菜单生成 HAP。公开工程默认无签名；安装运行按设备要求配置自己的调试签名，签名材料不提交源码。启动手机模拟器，运行 entry；选择混合局、6 个任务、适中，点击“立即开始”，确认清单后开局。点击转盘中心“开始”，待结果出现后交给下一位，再转一次。

    完成标志：构建日志为 BUILD SUCCESSFUL，生成本次新 HAP；首页名称正确，两轮任务不同，已交接扇区变灰、显示“完成”，剩余数减少。无签名打包成功不等于包可直接安装。

  3. 追踪任务生成与确认

    目标：理解用户设置如何变成一份确定的本局清单。

    操作：阅读 pages/SetupPage.ets、model/GameConfig.ets 和 engine/TaskEngine.ets。追踪模式、任务数和最高挑战程度的筛选；检查启用的自定义任务如何进入候选，Fisher–Yates 洗牌如何生成清单。分别体验重新生成、关闭确认层和确认开局。

    完成标志：清单为 2–20 条且符合玩法；自定义任务最多占 floor(任务数 × 0.5)；关闭确认层不开始游戏。生成清单和单次转盘命中是两套不同的随机操作。

  4. 理解转盘停止、结果动画和去重

    目标：让指针结果、任务卡片和本局完成状态保持一致。

    操作：阅读 engine/WheelRoundState.ets、components/WheelCanvas.ets 和 pages/WheelPage.ets。先从未处理索引选目标，再计算停止角度；观察旋转期间重复点击、命中强调及卡片入场。连续交接到最后一个任务，检查“完成本局”；也检查自愿跳过后交接。

    完成标志：旋转期间不会启动第二次抽取；卡片与指针对应，居中入场。交接后当前任务退出本局候选，扇区位置不变但变灰；本局耗尽可结束。新开一局可以再次出现旧任务。这是 2.5D Canvas 效果，不是独立 3D 引擎。

  5. 维护任务库并检查持久化

    目标：验证内置任务只读、自定义任务可维护及统一字数规则。

    操作：在任务库浏览和筛选 190 条内置任务；切到“我添加的”，新增“大冒险 / 轻松”的“在十秒内说出三种水果”，编辑、启停并重新启动元服务。阅读 store/LocalTaskStore.ets、store/PreferenceStore.ets 和 service/TaskTextRules.ets。尝试空正文、31 个汉字与包含 emoji 的任务。

    完成标志：重启后记录保留；内置内容没有编辑删除入口，停用项不参加抽样。正文最多 30 个 Unicode 码点，输入、保存、导入使用同一规则。格式校验不能判断任务是否安全适宜。

  6. 检查 JSON / TXT 导入导出

    目标：用版本化文件迁移自定义内容，避免覆盖已有数据。

    操作：先导出 JSON，再重复导入；阅读 TaskTransferValidator.ets 与 TaskTransferPackageBuilder.ets。检查未知版本、非法 JSON、重复任务、无效字段、超长正文以及超过 1 MiB 的文件。TXT 正文仍是 JSON，不是普通逐行任务列表。可用以下无私人信息的示例：

    {
  "format": "adventure-wheel-tasks",
  "version": 1,
  "tasks": [
    {
      "type": "dare",
      "level": "light",
      "text": "在十秒内说出三种水果",
      "enabled": true
    }
  ]
}

    完成标志：导入先显示新增、重复及无效条数，确认后只合并新任务，不覆盖原记录。传输字段只有正文、类型、程度、启用状态，不包含本地 ID、时间戳或内置任务。

  7. 验证实际文件接收与跨设备迁移

    目标：验证“带走任务”，不止验证“打开应用”。

    操作：点击“分享我的任务”，阅读 service/TaskTransferService.ets。确认生成的 adventure-wheel-my-tasks.txt 使用 JSON 正文，通过文件 URI、只读授权、text/plain 和 ohos.want.action.sendData 路由。目标列表取决于已安装应用；仅有一个匹配应用时可能直接打开。实际取得文件后，在另一设备导入，并重复导入检查去重。

    完成标志：接收端确实取得可读取的文件，目标设备恢复四个可携带字段。没有接收应用时使用“导出任务”作为替代路径。当前历史记录只确认系统路由启动，完整接收与再导入仍待验收。

  8. 运行规则测试并记录设备验收

    目标：分别给出规则、构建、设备和文件传递的结论。

    操作：在工程根目录使用 DevEco Studio 配套 Node.js 运行逻辑测试：

    $devEcoRoot = Read-Host '请输入 DevEco Studio 安装目录'
$env:DEVECO_SDK_HOME = Join-Path $devEcoRoot 'sdk'
& (Join-Path $devEcoRoot 'tools/node/node.exe') '.\tools\run-logic-tests.mjs'

    随后在已就绪的模拟器或手机验证三种玩法、数量边界、完成去重、持久化、取消文件选择、非法文件、分享和跨设备导入。记录设备 API、包版本、步骤、结果和脱敏截图。API 20 缺少设备时明确留为待测。

    可让 AI 执行：

    请自行启动当前可用的模拟器，完成基础功能测试并记录结果。能够自行处理的问题自行处理并验证；需要修改开发环境、变更需求或由我操作时，先告诉我，由我决定。不要把逻辑测试或打包成功当作设备测试通过。

    完成标志：输出 ALL 17 LOGIC TESTS PASSED，构建有新产物，设备验收逐项记录通过或待测。验证结束后删除自己创建的测试任务；本案例没有需释放的云资源。

高频问题排查

问题可能原因处理与恢复标志
构建报 00303313固定编译 SDK 与工具不匹配。检查配套 SDK；环境变更先确认。重新构建成功后，再做设备回归。
没有 signingConfig公开工程默认无签名。无签名打包是预期行为；安装按设备要求使用自己的调试签名。
找不到 Java构建进程未使用 IDE 配套 Java。核对当前进程的 JAVA_HOME 与 PATH，不直接修改系统环境。
TXT 导入失败正文不是约定的 JSON，或版本、长度不合法。按示例结构核对，先看导入统计，再确认合并。
分享没有选择面板系统只找到一个匹配接收入口。在目标应用确认文件实际送达，再执行导入；仅启动不算完成。
自定义任务未入选停用、玩法不匹配，或随机抽样未选中。检查最高挑战程度和 50% 上限，重新生成并查看清单。

安全与交付
