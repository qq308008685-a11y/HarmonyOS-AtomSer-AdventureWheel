快速体验

这条路线使用现成代码。环境就绪后预计 30 分钟，完成“生成清单 → 确认开局 → 抽取并交接 → 浏览任务库”。从空项目独立构建请看下方的完整实践。

 版本与环境   本案例为纯本地手机元服务：编译与目标 API 26（26.0.0）、最低兼容 API 20（6.0.0(20)）。首次获取源码、素材、SDK 和依赖时需联网，SDK、Java、Node 与构建工具须匹配，玩法不依赖服务器、数据库或游戏账号。选择方式 A（云端工作区）或方式 B（本地开发）即可；在线工作区与云手机的配额或费用以实际账号及平台提示为准。

 签名边界   公开工程默认不配置签名，可生成无签名 HAP。本地模拟器按官方无签名方式调试；真机需在 DevEco Studio 的 File -> Project Structure -> Signing Configs 配置自己的调试签名，云手机按平台实际要求。签名、口令与私人任务不提交公仓；登录、隐私同意与授权由本人决定。构建、安装与启动分别核对。

超限备份的安全恢复

自定义任务导出没有总量上限，但每份导入文件最多 1000 条、大小不超过 1 MiB（1,048,576 字节）；JSON 与正文为 JSON 的 TXT 使用同一版本 1 契约。超限备份先在电脑上用工程附带的 tools/split-task-backup.mjs 安全拆分，再按编号逐份导入；不修改原备份、字段或任务顺序，也不以删任务规避限制。

完整操作与可复制提示词见批量任务迁移说明。在目标设备进入 任务库 → 我添加的 → 导入任务，逐份核对新增、重复与无效统计，并抽查正文、类型、程度和启用状态；目标设备实际恢复成功前保留原设备和完整备份。拆分核对通过不能代替目标设备恢复验收，明文备份只发给确认的接收对象。

✅ 完成标志：超限备份已在目标设备逐份导入并核对一致，确认恢复无误后再决定是否清理旧备份。
